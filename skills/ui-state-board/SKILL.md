# UI 状态画布

技能自带可直接运行的 [画布应用](assets/canvas/index.html)及[配置样例](assets/canvas/board.json)。画布只负责摆放和检查页面。AI 在项目中直接编写 HTML/CSS/JS 或项目框架组件，再把页面入口填进配置。可以先在 `assets/canvas/` 运行下方静态服务器命令，打开 `http://127.0.0.1:1104/` 查看两种状态的示例。

**产物集中到独立工作区。** 开工时先确定项目根目录，在其下为本次任务选定一个独立工作区目录，同一任务的后续迭代沿用该目录。画布放在工作区的 `board/`，本次新建的原型、设计稿、评审数据和素材也集中在这一工作区。复用已有前端时，画布通过项目路由或相对路径加载现有实现。

**开工前确认视口尺寸。** 先确定目标设备，写明每套状态图的视口宽高（CSS 像素）。沿用任务指定的尺寸，手机未指定时默认 390 × 844。同一套状态的整屏生图、HTML/CSS 布局、局部装饰尺寸与定位、截图对照和画框内的实际渲染都以该视口为准。如需桌面版，先单独确定宽屏视口，并在桌面状态间统一使用。

1. **列出状态。** 先写用户从进入到完成目标的最短路径，再补会改变画面或下一步操作的分支，如输入有误、处理中、失败重试和空列表。沿用已有 PRD、目标设备和参考风格；缺少会影响设计的信息时再问。已有截图可作为还原的视觉参考。已有前端时直接复用该实现。
2. **可选：生成整屏设计稿。** 需要先探索或对齐视觉方案时，用图像生成工具为第 1 步列出的每个状态生成一张整屏设计稿。先生成主屏，再以主屏为参考生成其他状态，保持同一设备下的布局和组件风格一致，让每个状态的变化清楚可见。整屏稿按已确认的视口宽高比构图。生图工具的输出尺寸受限时，先将各稿裁切或等比缩放到该视口对应的画布尺寸，再用作还原参考。跳过这一步时，直接进入 HTML/CSS 制作。
3. **先做一屏，再派生。** 有整屏设计稿时，参照各稿用 HTML/CSS 还原布局和状态变化，文案与状态以 PRD 或用户流程为准。用一套 HTML/CSS 组件搭好主屏，其他状态只改发生变化的区域。弹层保留原页面作背景；同一任务的示例图、输入内容、金额和余额前后接得上。样图可单独生成，界面文字、按钮统一排版。

   **复杂装饰的还原。** 先评估背景曲线、半透明色块和图形装饰能否用前端代码还原。每轮调整后在目标视口渲染截图，对照设计稿或视觉参考检查形状、位置、颜色和透明度。同一处装饰最多尝试三轮，第三轮后仍有明显差距时，用图像生成工具单独生成该装饰的 PNG，按设计稿的尺寸和位置放入页面。需要透出底色时使用透明背景。文字、按钮和布局继续用 HTML/CSS 实现。

4. **给页面元素加 ID。** 在共用的前端代码里，从页面根元素到最深层的元素节点都设置实际的 `id` 属性，包括文字容器、按钮、图标、SVG 子元素和装饰。每个状态里的 ID 必须唯一且稳定，列表项按稳定的条目标识区分。跨状态用「状态 + 元素 ID」定位元素。
5. **接入内置画布。** 将 `assets/canvas/` 复制到本次工作区的 `board/`，并让项目服务能访问该目录。编辑副本的 `board.json`，在 `groups` 中按页面分组，填写页面名和已确认的 `viewport.width`、`viewport.height`。组内按操作顺序填写 `states`，每项需要状态名 `name` 和页面入口 `src`。入口可写相对画布的路径或项目路由，也可用同一入口的不同查询参数展示各状态。在 `board.json` 顶层填写可选的 `prototypeSrc` 指向可独立操作的页面入口。填写后，顶部会显示「单独打开原型」，点击即在新标签页打开。使用项目自己的原型入口替换示例地址；仅使用画布时可省略该字段。替换示例配置后可移除副本中的 `example/`。每个画框下方会显示状态名称。如需桌面状态，在末尾单独分组。左侧目录按页面分组列出全部状态，点击即可将对应画框居中并缩放到合适大小。支持拖拽平移、缩放和回到 100%，并提供检查模式，点选画框内的元素可查看其 ID，能选到最底层元素。选中带 ID 的元素后，点击「复制组件 ID」即可一键复制页面名、状态名和元素 ID。

   **画框复用前端实现。** 画框直接加载与实际前端相同的页面组件、样式、素材和渲染逻辑，通过状态参数或预置数据展示各个状态。用同一个本地站点提供画布和前端路由，保证画布能读到页面元素。每个画框用固定宽高的 iframe 建立独立视口。画布缩放只改变外层显示比例，画框内部始终按已确认的视口渲染。

6. **验收并交付。** 提供独立工作区的路径、浏览器可打开的画布入口和启动方式。现有前端用项目自己的开发服务器。纯静态项目在根目录执行下方命令，然后打开画布对应的 URL。交付前逐个核对页面分组、状态名称和顺序，检查目录能否跳到各个状态和已配置的原型入口能否独立打开，读取每个画框的实际视口宽高，检查各状态的元素树有无缺失或重复的 ID，确认能点到最底层元素并复制正确的定位信息，再验证平移、缩放及画框与前端的代码复用。

```sh
python3 -m http.server 1104 --bind 127.0.0.1
```
